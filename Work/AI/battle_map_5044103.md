## Q1: skill_entry_model_monster3 表中 battle_entry_action 92601XX 的技能机制是什么

### 结论

`92601XX` 是一组“随机选择线路 -> 生成/预警水晶点位 -> 检测板块内目标 -> 通知 5044104 击碎水晶并触发后续模块”的双子姐姐水晶机制。

从 `9260101` 起手，技能不会同时走完全部线路，而是通过 `9260120` 在三条线路中随机选择一条：

| 随机结果 | 线路 | 初始点位偏移 | 后续检查板块 | 击碎水晶模块 |
| --- | --- | ---: | --- | --- |
| `9260121` | 左线 | `x=-1500` | 板块 `1`、`6` | `9260145`、`9260150` |
| `9260122` | 中线 | `x=0` | 板块 `2`、`5` | `9260146`、`9260149` |
| `9260123` | 右线 | `x=1500` | 板块 `3`、`4` | `9260147`、`9260148` |

### 执行链路

1. `9260101`
   - 普通 action 节点，`next=9260120`。

2. `9260120`
   - `typ=10045`，含义是按配置随机并保存随机值。
   - `data=[1,2,9260121,100,9260122,100,9260123,100]`。
   - `kind=1` 表示排除当前 `val` 后随机，`isTrigger=2` 表示随机结果会直接触发对应模块。
   - 三条线路权重都是 `100`，因此等权随机。

3. `9260121/9260122/9260123`
   - 三个节点分别进入左、中、右线路。
   - 各自 `next` 到 `9260124/9260125/9260126`。

4. `9260124/9260125/9260126`
   - `typ=10074`，代码注释为“有初始坐标的 buff 模块”。
   - 三个模块使用同一个表现特效 `effect=1793624`。
   - `data` 的第三位分别为 `-1500 / 0 / 1500`，对应左、中、右三个初始点位偏移。
   - 持续时间使用 `time[0]=-91`，即读取技能参数 1。
   - 结束或触发后进入 `9260127/9260128/9260129`。

5. `9260127/9260128/9260129`
   - 等待时间使用 `time[0]=-95`，即读取技能参数 5。
   - 分别进入 `9260130/9260131/9260132`。

6. `9260130/9260131/9260132`
   - 再次使用 `typ=10074`，表现特效改为 `effect=1793625`。
   - 仍按左、中、右使用 `x=-1500 / 0 / 1500`。
   - 固定 `3000ms` 后触发两个分支：
     - 左线：`9260133`、`9260138`
     - 中线：`9260134`、`9260137`
     - 右线：`9260135`、`9260136`

7. `9260133` 到 `9260138`
   - 这些是分支延迟节点。
   - 左、中、右线路最终分别覆盖两个板块：
     - 左线：`9260133 -> 9260139/9260145`，`9260138 -> 9260144/9260150`
     - 中线：`9260134 -> 9260140/9260146`，`9260137 -> 9260143/9260149`
     - 右线：`9260135 -> 9260141/9260147`，`9260136 -> 9260142/9260148`

8. `9260139` 到 `9260144`
   - `typ=100`，即伤害命中模块。
   - `target=[123,N]`，`123` 的代码注释是“取指定板块的所有敌人”，`N=1..6`。
   - `data=[0,0,0,1,-92]`，伤害公式最终读取技能参数 2。
   - 作用是对对应板块内目标造成一次技能伤害。

9. `9260145` 到 `9260150`
   - `typ=1914`，代码注释为“双子姐姐击碎水晶”。
   - `target=[39,5044104]`，`39` 是“己方队伍中指定 id 的目标”，这里固定找 `5044104`。
   - `data[0]=1` 表示“击碎水晶”，`data[1]=20082` 表示触发事件“当目标击碎水晶”。
   - 后续模块按水晶位置分发：
     - `9260145 -> 9261035, 9260833`
     - `9260146 -> 9261036`
     - `9260147 -> 9261037, 9260834`
     - `9260148 -> 9261038, 9260835`
     - `9260149 -> 9261039`
     - `9260150 -> 9261040, 9260836`

### 机制解读

- 这是一个三选一的水晶线路机制，不是六个板块同时触发。
- 随机到某条线路后，该线路会在两个板块上落点：左线对应板块 `1/6`，中线对应 `2/5`，右线对应 `3/4`。
- 每个落点有两类效果：
  - 对板块内敌人造成一次伤害。
  - 让 `5044104` 目标触发“击碎水晶”事件，并把对应后续模块作为事件参数传下去。
- `9260145/9260147/9260148/9260150` 会额外带一个 `92608XX` 后续模块；`9260146/9260149` 只带 `92610XX` 后续模块。也就是说边缘或特定点位的水晶破碎后续效果比中间两个点位多一组。

### 参考字段

- 数据源：`etc/game/data/ConfigCN/skill_entry_model_monster3.json`
- 同名配置：`ConfigGL`、`ConfigTW` 中 `92601XX` 片段与 `ConfigCN` 内容一致。
- 关键代码含义：
  - `typ=10045`：`entryTypeRandomVal`，根据随机规则保存随机值。
  - `typ=10074`：`entryTypeBuffModelWithInitPos`，有初始坐标的 buff 模块。
  - `typ=100`：`entryTypeDamageHit`，伤害命中。
  - `typ=1914`：`entryTypeTwinMirrorBreakCrystal`，双子姐姐击碎水晶。
  - `typ=20082`：`entryTypeWhenTargetBreakCrystal`，当目标击碎水晶。

## Q2: skill_entry_model_monster3 表中 battle_entry_action 92600XX 的技能机制是什么

### 结论

`92600XX` 是双子姐姐/镜像水晶机制的“战斗开场初始化 + 阶段锁血 + 镜像区表现同步”模块组。

它的入口是 `9260001`：在战斗开始时触发一批子模块，主要做三类事情：

1. 检测场上是否已有关键水晶/镜像模块，并按检测结果播放不同战报特效。
2. 给自身挂多段锁血阈值，限制 Boss 在关键血线前被直接打穿。
3. 根据血量区间和是否低于阈值，给自己添加或清除一个提示 buff 图标 `9260041`。

### 入口与总链路

`9260001`

- `kind=2`，事件模块。
- `typ=20003`，代码注释为“战斗开始”。
- `time=[-1,-1,1000,0]` 一类配置表示长期/循环性质，入口本身在战斗开始时触发。
- 触发子模块：
  - `9260020`
  - `9260022`
  - `9260030`
  - `9260037` 到 `9260040`
  - `9260042` 到 `9260049`

### 镜像/水晶存在检测与表现

这一组负责根据目标身上是否存在指定模块，播放不同的客户端战报特效。

| 模块 | 作用 |
| --- | --- |
| `9260020 -> 9260033` | 开场后检测敌方目标是否存在 `9260730`。不存在则触发 `9260021`，播放特效 `1100`。 |
| `9260022 -> 9260023/9260025/9260024` | 以敌方队伍为目标，先检测 `9260730`，不通过再检测 `9262520`，再判断是否处于镜像板块。 |
| `9260026` | 检测链完全不通过时播放特效 `1213`。 |
| `9260027` | 存在 `9260730` 时播放特效 `1214`。 |
| `9260028` | 镜像板块判断通过时播放特效 `1216`。 |
| `9260029` | 镜像板块判断不通过时播放特效 `1215`。 |
| `9260030 -> 9260031/9260034` | 自身检测 `9262536`，不通过再检测 `9264244`。 |
| `9260035/9260036/9260032` | 根据检测结果分别播放 `effect=1793644 / 1793643 / 1793642` 的初始坐标 buff 表现。 |

关键类型：

- `typ=30000`：判断目标是否存在指定模块 ID。
- `typ=30124`：判断目标是否在镜像板块；配置 `data=[6]` 表示镜像板块起始索引为 `6`，目标所在 `areaIndex >= 6` 时通过。
- `typ=116`：给目标发送战报特效，只给 target 发。
- `typ=10074`：有初始坐标的 buff 表现模块。

### 多段锁血

`9260037` 到 `9260040` 是四个锁血模块：

| 模块 | `typ` | 锁血阈值 |
| --- | --- | ---: |
| `9260037` | `1805` | `90%` |
| `9260038` | `1805` | `80%` |
| `9260039` | `1805` | `60%` |
| `9260040` | `1805` | `20%` |

`typ=1805` 的代码注释是“大蛇本锁血 Buff，只对怪物生效”。伤害结算时如果剩余血量会低于当前最高锁血阈值，就把血量拉回对应百分比，并触发该锁血模块的后续。

这四个锁血模块的 `next` 都指向 `9260050`，而 `9260050` 会移除 `9260041`。

### 血量提示 Buff

`9260041` 是一个纯提示 buff：

- `buff_icon=10010`
- `layer_default=1`
- `layer_max=1`
- `refresh=7`

它本身没有复杂 action，主要用于 UI 或战斗表现提示。

添加和清除规则分两类：

1. 受伤后血量落入区间时添加 `9260041`

| 模块 | `typ=20001` 区间 | 触发 |
| --- | --- | --- |
| `9260042` | `(89%, 90%]` | 添加 `9260041` |
| `9260043` | `(79%, 80%]` | 添加 `9260041` |
| `9260044` | `(59%, 60%]` | 添加 `9260041` |
| `9260045` | `(19%, 20%]` | 添加 `9260041` |

2. 当前血量低于阈值时清除 `9260041`

| 模块 | `typ=20018` 条件 | 触发 |
| --- | --- | --- |
| `9260046` | `hp <= 89%` | `9260050` 清除 `9260041` |
| `9260047` | `hp <= 79%` | `9260050` 清除 `9260041` |
| `9260048` | `hp <= 60%` | `9260050` 清除 `9260041` |
| `9260049` | `hp <= 19%` | `9260050` 清除 `9260041` |

`9260050` 的 `typ=10018`，含义是移除指定模块，这里移除 `9260041`。

### 机制解读

- `92600XX` 更像 Boss 机制的“底座”，不是具体攻击招式。
- 它在战斗开始时注册一批监听与表现模块，后续由战斗事件驱动。
- 锁血点是 `90/80/60/20` 四档；到达阈值附近时会显示 `9260041` 提示，突破阈值后清除提示。
- `9260020` 到 `9260036` 负责根据场上是否存在镜像/水晶相关模块，区分播放不同表现，尤其是 `9260730 / 9262520 / 9262536 / 9264244` 这些关键状态模块。

### 参考字段

- 数据源：`etc/game/data/ConfigCN/skill_entry_model_monster3.json`
- 同名配置：`ConfigGL`、`ConfigTW` 中 `92600XX` 片段与 `ConfigCN` 内容一致。
- 关键代码含义：
  - `typ=20003`：`entryTypeWhenBattleStart`，战斗开始。
  - `typ=30000`：`entryTypeIsExistModelId`，目标是否存在指定模块 ID。
  - `typ=30124`：`entryTypeIsTargetInMirrorArea`，目标是否在镜像板块。
  - `typ=116`：`entryTypeBattleEffectIdByRole`，只给目标发送战报特效。
  - `typ=10074`：`entryTypeBuffModelWithInitPos`，有初始坐标的 buff 模块。
  - `typ=1805`：`entryTypeLimitHp`，怪物锁血。
  - `typ=20001`：`entryTypeWhenHpRangeHit`，受伤后血量落入区间。
  - `typ=20018`：`entryTypeWhenHpRangeRate`，当前血量低于或高于阈值。
  - `typ=10018`：`entryTypeClearModel`，移除模块。

## Q3: skill_entry_model_monster3 表中 battle_entry_action 92604XX 的技能机制是什么

### 结论

`92604XX` 是一组“非重复点名玩家 -> 按玩家所在镜像板块生成水晶预警 -> 覆盖多个板块造成伤害 -> 联动 9260145~9260150 击碎水晶事件”的技能机制。

它和 `92601XX` 共用后半段“击碎水晶”链路，但 `92604XX` 的点位选择更复杂：不是简单三选一，而是先从未被记录过的目标里选人，再根据目标的 `navAreaInfo.areaIndex` 选择六个点位中的一个。

### 入口链路

`9260401`

- 同时触发 `9260451` 和 `9260420`。
- `9260451` 用来判断是否还有未点名目标；如果没有可选目标，会触发打断。
- `9260420` 是主体流程，目标配置为 `target=[139,9262811,23,1]`。

`9262811`

- 是这组机制的记录模块。
- `9260421` 会通过 `typ=20`、`data=[41,9262811]` 把当前目标写入 `9262811.commonRole`。
- `target=139` 的代码含义是“选择不在记录模块中的角色”，所以后续点名会避开已经记录过的目标。

### 目标选择与点名表现

1. `9260420`
   - 选择未记录过的敌方角色。
   - 触发 `9260421` 和 `9260422`。
   - `next=9900350`，该模块是 `typ=91`，作用是让来源看向目标。

2. `9260421`
   - `typ=20`，记录目标。
   - `data=[41,9262811]`，含义是把上个模块目标写入来源身上的 `9262811.commonRole`。

3. `9260422`
   - 使用 `effect=1793639` 做点名前摇/预警表现。
   - 持续时间读取 `-90`，即技能吟唱时间。
   - 同时触发 `9260449`，并在结束后进入 `9260423`。

### 点位预警

`9260449 -> 9260450` 是一段额外预警链：

- `9260449` 的时间为 `[-90,0,500,0]`，可理解为围绕吟唱时间做偏移触发。
- `9260450` 是 `typ=10051`，`kind=21`，即按目标的音游板块 `navAreaInfo.areaIndex` 选择模块。
- 它会在六个固定点位中播放 `effect=1793627`：

| 点位模块 | 坐标偏移 |
| --- | --- |
| `9260443` | `(-750, -1500)` |
| `9260444` | `(-750, 0)` |
| `9260445` | `(-750, 1500)` |
| `9260446` | `(750, 1500)` |
| `9260447` | `(750, 0)` |
| `9260448` | `(750, -1500)` |

### 主水晶生成与板块伤害

`9260423`

- `typ=10051`，`kind=21`。
- 根据目标的 `navAreaInfo.areaIndex` 从 `9260424~9260429` 中选择一路。
- 配置里六个模块重复两轮，是为了覆盖 `areaIndex` 超过 5 的镜像板块映射。

`9260424~9260429`

- 分别进入六个水晶点位：

| 分支 | 主表现模块 | 坐标偏移 | 后续覆盖板块 |
| --- | --- | --- | --- |
| `9260424` | `9260430` | `(-750, -1500)` | `1/2/3/6` |
| `9260425` | `9260431` | `(-750, 0)` | `1/2/3/5` |
| `9260426` | `9260432` | `(-750, 1500)` | `1/2/3/4` |
| `9260427` | `9260433` | `(750, 1500)` | `4/5/6/3` |
| `9260428` | `9260434` | `(750, 0)` | `4/5/6/2` |
| `9260429` | `9260435` | `(750, -1500)` | `4/5/6/1` |

`9260430~9260435`

- `typ=10074`，有初始坐标的 buff/表现模块。
- 统一播放 `effect=1793628`。
- 固定 `1000ms` 后触发 4 个后续节点。

`9260436~9260441`

- 每个节点延迟 `500ms` 后同时做两件事：
  - 触发对应板块伤害 `9260461~9260466`。
  - 触发 `9260145~9260150` 的击碎水晶事件。

对应关系：

| 节点 | 伤害板块 | 击碎水晶模块 |
| --- | --- | --- |
| `9260436` | `9260461`，板块 1 | `9260145` |
| `9260437` | `9260462`，板块 2 | `9260146` |
| `9260438` | `9260463`，板块 3 | `9260147` |
| `9260439` | `9260464`，板块 4 | `9260148` |
| `9260440` | `9260465`，板块 5 | `9260149` |
| `9260441` | `9260466`，板块 6 | `9260150` |

`9260461~9260466`

- `typ=100`，伤害命中。
- `target=[123,N]`，表示取指定板块 `N` 内所有敌人。
- `data=[0,0,0,1,-91]`，伤害值读取技能参数 1。
- 每次伤害后 `next=9260442`。

### 易伤 Debuff

`9260442`

- `typ=306`，代码注释为“受到最终伤害额外”，也就是易伤/额外受伤。
- `time[0]=-92`，持续时间读取技能参数 2。
- `data=[1,-93]`，数值读取技能参数 3。
- `buff=2`，`buff_icon=20010`，最大 `99` 层。
- `dataCondition=[[1,92604]]`，限定在当前 `92604` 技能相关条件下生效。

### 无目标时的打断逻辑

`9260451`

- `typ=30126`，判断记录模块是否还有可选择的目标。
- `data=[9262811]`，检查 `9262811.commonRole` 里是否已经记录了所有可选敌人。
- 如果判断不通过，触发：
  - `9260452`：打断自身当前技能。
  - `9260453`：对己方队伍中特定类型目标执行打断。

这表示当没有新的可点名目标时，该技能会主动中断，避免继续走无效点名。

### 机制解读

- `92604XX` 是点名型水晶机制：优先选择未被 `9262811` 记录过的敌方角色。
- 目标所在镜像/音游板块决定水晶落点；一个落点会覆盖 4 个板块，而不是只打目标所在板块。
- 伤害链路复用了 `9260145~9260150` 的“击碎水晶”模块，所以它会继续触发 `5044104` 相关的水晶破碎后续。
- 命中的板块目标会获得 `9260442` 易伤 debuff，使后续受到最终伤害增加。

### 参考字段

- 数据源：`etc/game/data/ConfigCN/skill_entry_model_monster3.json`
- 同名配置：`ConfigGL`、`ConfigTW` 中 `92604XX` 片段与 `ConfigCN` 内容一致。
- 关键代码含义：
  - `target=139`：选择不在记录模块中的角色。
  - `typ=20`：`entryTypeRecordTarget`，记录目标。
  - `typ=91`：`entryTypeLogLookTarget`，看向目标。
  - `typ=10051`：`entryTypeTriggerMod`，按配置触发模块；`kind=21` 表示按 `navAreaInfo.areaIndex` 选模块。
  - `typ=10074`：`entryTypeBuffModelWithInitPos`，有初始坐标的 buff/表现模块。
  - `typ=100`：`entryTypeDamageHit`，伤害命中。
  - `typ=306`：`entryTypeFinDamageHitExtra`，受到最终伤害额外。
  - `typ=30126`：`entryTypeRecordModelHasTargetRole`，判断记录模块是否还有可选择目标。
  - `typ=826`：`entryTypeBreakCurrentSkill`，打断当前技能。

## Q4: skill_entry_model_monster3 表中 battle_entry_action 92624 的技能机制是什么

### 结论

`92624` 是双子姐姐/镜像战斗里的“双目标召唤与站位同步”机制。

它会在技能参数 1 指定的延迟后，同时处理 `5044103` 和 `5044104` 两个目标：分别把它们召唤/定位到左右两侧坐标，短暂播放表现，然后给目标设置不可选中、无法普攻、强制锁定 Tank 等状态。最后延迟 1 秒清理 `9260038`，也就是前面 `92600XX` 里的 80% 锁血模块。

### 主链路

`9262401`

- `time[0]=-91`，读取技能参数 1 作为持续/延迟时间。
- `next=[9262420,9262422,9262430]`，同时进入左右目标处理和锁血清理链。

### 左右双目标召唤/定位

`9262420`

- `typ=825`，召唤。
- `data=[8,5044103,-3800,-500,1,9262424]`。
- 含义：
  - 召唤类型 `8`：按世界坐标设置坐标，且不走移动。
  - 目标 ID：`5044103`。
  - 坐标：`(-38, -5)`，配置里 `-3800/-500` 会按 `0.01` 换算。
  - 附加模块：`9262424`。
- `dataCondition=[[999,0]]`，表示只在某个条件分支为 `0` 时生效。

`9262422`

- 同样是 `typ=825` 召唤。
- `data=[8,5044104,-3800,500,1,9262425]`。
- 含义：
  - 目标 ID：`5044104`。
  - 坐标：`(-38, 5)`。
  - 附加模块：`9262425`。
- `dataCondition=[[999,1]]`，对应另一个条件分支。

### 召唤后的表现与位置修正

`9262424` / `9262425`

- `typ=98`，特殊效果表现。
- `data=[2]`。
- `time=200ms`。
- 都绑定 `9262421`，所以清理时会联动状态模块。
- 后续分别进入：
  - `9262424 -> 9262426`
  - `9262425 -> 9262427`

`9262426`

- `typ=283`，设置目标位置。
- `data=[0,0,8,-1326,-500,1]`。
- 把目标设置到 `(-13.26, -5)`。

`9262427`

- `typ=283`，设置目标位置。
- `data=[0,0,8,-1326,500,1]`。
- 把目标设置到 `(-13.26, 5)`。

这说明前一段 `825` 更像是把两个目标生成/放到较远初始点，随后 `283` 再把它们同步到实际战斗表现位置。

### 目标状态控制

`9262421`

- `typ=801`，不能被选中。
- 后续触发：
  - `9262423`
  - `9262428`

`9262423`

- `typ=299`，无法普攻。
- `data=[1,1]`。
- 作用是让上个模块目标进入不可普攻状态。

`9262428`

- `typ=857`，持续设置目标，给同组怪物使用。
- `target=[149,1]`，`149` 是“敌方 Tank，保底当前目标”。
- `data=[1]`，表示让来源强制把目标设为该 Tank。

整体效果是：被处理的镜像/召唤目标不能被玩家选中，同时自身也不能普攻，并持续锁定敌方 Tank。

### 锁血清理

`9262430 -> 9262429`

- `9262430` 延迟 `1000ms` 后进入 `9262429`。
- `9262429` 是 `typ=10018`，移除模块。
- `data=[9260038]`，即移除 `9260038`。

`9260038` 是 `92600XX` 里的 `80%` 锁血模块：

- `typ=1805`
- `data=[80]`

所以 `92624` 机制启动后，会在 1 秒后解除 80% 锁血点。

### 机制解读

- `92624` 不是直接伤害技能，而是战斗阶段转换/双子站位同步机制。
- 它围绕 `5044103` 和 `5044104` 两个关键目标工作，把它们分别处理到左右两侧。
- 处理后的目标会进入不可选中、不可普攻，并强制面向/锁定 Tank 的状态。
- 该机制还负责阶段推进：通过清理 `9260038`，解除 Boss 的 80% 锁血。

### 参考字段

- 数据源：`etc/game/data/ConfigCN/skill_entry_model_monster3.json`
- 同名配置：`ConfigGL`、`ConfigTW` 中 `92624` 片段与 `ConfigCN` 内容一致。
- 关键代码含义：
  - `typ=825`：`entryTypeSummon`，召唤。
  - `typ=98`：`entryTypeBattleEffectId`，特殊效果表现。
  - `typ=283`：`entryTypeRefreshTargetPos`，设置目标位置。
  - `typ=801`：`entryTypeUnSelect`，不能被选中。
  - `typ=299`：`entryTypeCannotDefAtk`，无法普攻。
  - `target=149`：敌方 Tank，保底当前目标。
  - `typ=857`：`entryTypeForceSetTarget`，持续设置目标。
  - `typ=10018`：`entryTypeClearModel`，移除模块。
