## Q1: etc/game/data/ConfigCN/skill_entry_model_monster3.json 里的 910002XX 模块是什么？

### 问题

`etc/game/data/ConfigCN/skill_entry_model_monster3.json` 中 `910002XX` 这些模块的作用是什么？请参考 `battle_entry_type.go` 等战斗脚本详细介绍。

### 结论

`910002XX` 是世界 Boss 910002 的玩家侧机制，技能文案是「进入冥界 / Gate of Underworld」。它不是单个伤害技能，而是一套按钮切换机制：

- 玩家可点击按钮在【凡世】和【冥界】之间切换。
- `91000228` 是【冥界】状态核心模块，类型 `305`，对应 `entryTypeFinDamageMakeExtra`，配置值 `[1,25]`，表示处于冥界时获得额外最终伤害提高。
- `91000237` 是【冥炎】保护/标记模块，持续 15 秒，带 buff 图标 `10032` 和特效 `1792761`。
- `91000244` 是【冥炎】相关表现模块，特效 `1792795`，由 `91000237` 到期后通过 `91000246` 清除。
- `91000249` 是冥界惩罚层数/图标，buff 图标 `20002`，最大 99 层。
- 在【冥界】中如果没有【冥炎】，会每秒触发惩罚伤害并叠 `91000249`。
- 在【凡世】中如果携带【冥炎】，会每秒触发小额伤害。
- `91000221` 保存按钮状态值，按钮点击入口由客户端 `OpType == 20` 触发，服务端走 `actionHandleCommonLogicOpType20`。

### 关联配置与代码入口

- 模块配置：`etc/game/data/ConfigCN/skill_entry_model_monster3.json`
- 技能文案：`etc/game/data/ConfigCN/global_text_skill.json`
  - `910002_skillname`: 进入冥界
  - `910002_skillDec`: 描述了冥界增伤、无冥炎扣血、凡世携带冥炎扣血、再次点击返回凡世。
- 技能配置：`etc/game/data/ConfigCN/monster_skill.json`
  - `910002` 的 `model_id` 是 `910002`，`value1/value2/value3` 分别配置为 `[25]`、`[25]`、`[7]`。
- 世界 Boss 地图：`etc/game/data/ConfigCN/world_boss_map.json`
  - `910002` 对应 `MonsterID = 999002`。
- 类型枚举：`internal/battle/battle_entry_type.go`
- 按钮与动作逻辑：`internal/battle/battle_entry_action.go`
- 事件触发逻辑：`internal/battle/battle_entry_event.go`
- 目标选择解释：`internal/battle/battle_entry_target.go`
- 时间字段解释：`internal/battle/battle_entry_time.go`

### 字段速读

- `time = [持续时间, 执行次数, 执行间隔, 是否延迟]`，单位通常按毫秒转秒；`-1` 表示不限制。
- `target = [1]` 表示自身，`target = [3]` 表示敌方队伍，`target = [5]` 表示上个模块目标。
- `kind = 1` 是行为模块，`kind = 2` 是事件模块，`kind = 5` 是判断模块。
- 本组里最关键的 `typ`：
  - `0`: 直接执行/串联。
  - `1`: 时间等待。
  - `97`: 值类型伤害。
  - `305`: 造成最终伤害额外提高。
  - `1052`: 设置某个模块的 `val`。
  - `1902`: 副本技能 CD 战报/倒计时。
  - `1920`: 冥染龙按钮状态模块。
  - `1921`: 冥染龙按钮状态同步战报。
  - `10018`: 清除指定模块。
  - `20003`: 战斗开始事件。
  - `20020`: 角色死亡事件。
  - `30000`: 判断目标是否存在指定模块。

### 主流程一：战斗开始初始化

`91000201` 是战斗开始事件根模块：

- `kind = 2`, `typ = 20003`, 即 `entryTypeWhenBattleStart`。
- 战斗开始后触发 `91000220`、`91000231`、`91000241`、`91000248`。

`91000220` 将机制挂到玩家身上：

- `target = [3]`，从 Boss 视角选择敌方队伍，也就是玩家。
- `next = [91000221, 91000252]`。
- `91000221` 初始化按钮状态。
- `91000252` 监听玩家死亡后的按钮重置。

`91000221` 是按钮状态核心：

- `typ = 1920`, 即 `entryTypeDarkDragonBtn`。
- `data = [1, 2, 91000223, 91000222, 0]`。
- 初始化 `val = 1`，`maxVal = 2`。
- `data[2] = 91000223` 是点击按钮后实际运行的模块。
- `data[3] = 91000222` 是按钮状态同步模块。
- `next = [91000222]`，初始化后立刻同步一次 UI 状态。

`91000248` 是每秒同步按钮状态的兜底循环：

- `time = [-1, -1, 1000, 0]`，无限持续、无限次数、每秒触发。
- `trigger = [91000222]`。

### 主流程二：按钮点击如何切换冥界/凡世

客户端点击该机制按钮时，战斗服处理 `OpType == 20`，调用 `actionHandleCommonLogicOpType20`。

该函数会找到玩家身上的 `entryTypeDarkDragonBtn` 模块，也就是 `91000221`：

- 如果 `val == 0` 或 `val == 2`，直接返回，按钮处于冷却/不可点状态。
- 其他状态下，读取 `data[2]`，也就是 `91000223`，并添加该模块。

`91000223` 继续串到 `91000230`。

`91000230` 是切换分支判断：

- `kind = 5`, `typ = 30000`，判断目标是否存在 `91000228`。
- 如果存在 `91000228`，说明当前在【冥界】，走 `trigger = [91000229, 91000224, 91000227]`，即退出冥界。
- 如果不存在 `91000228`，说明当前在【凡世】，走 `not_pass_trigger = [91000228, 91000235, 91000240]`，即进入冥界。

进入【冥界】时：

- `91000228`: 添加冥界增伤状态。
- `91000240`: 将按钮状态设置为 `2`，表示进入冥界后的短暂不可点。
- `91000235 -> 91000250 -> 91000234`: 走 2 秒 CD 表现，最后将按钮状态设置为 `3`，表示已在冥界且可以再次点击返回凡世。

退出【冥界】时：

- `91000229`: 清除 `91000228`。
- `91000227`: 将按钮状态设置为 `0`，表示返回凡世后的短暂不可点。
- `91000224 -> 91000225 -> 91000226`: 走 2 秒 CD 表现，最后将按钮状态设置为 `1`，表示已在凡世且可以再次点击进入冥界。

按钮状态可以按这个方式理解：

| `91000221.val` | 含义 |
|---:|---|
| 0 | 凡世侧冷却中，不可点击 |
| 1 | 凡世侧可点击，点击后进入冥界 |
| 2 | 冥界侧冷却中，不可点击 |
| 3 | 冥界侧可点击，点击后返回凡世 |

### 主流程三：冥界状态与冥炎保护

`91000228` 是【冥界】状态：

- `typ = 305`, 即 `entryTypeFinDamageMakeExtra`。
- `data = [1,25]`，按配置直接提供 25 点最终伤害额外提高。
- `layer_default = 1`, `layer_max = 1`，不可叠多层。

`91000236` 是外部攻击链路进入【冥炎】逻辑的入口：

- 它本身在本文件内定义，但多处其他怪物技能模块会通过 `next = [91000236]` 调进来。
- `typ = 30000`, `data = [91000228]`，判断目标是否处于冥界。
- 如果目标不在冥界，走 `not_pass_trigger = [91000237, 91000244, 91000251]`：
  - `91000237`: 添加冥炎 buff。
  - `91000244`: 添加冥炎表现特效。
  - `91000251`: 清除 `91000249` 惩罚层数。

`91000237` 是【冥炎】本体：

- `typ = 1`, `time = [15000,1,0,0]`，持续 15 秒。
- `dataCondition = [[45, 91000228]]`，条件类型 45 是角色当前是否存在指定模块。
- `effect = 1792761`, `buff_icon = 10032`。
- `next = [91000246]`，结束后清除 `91000244`。

`91000244` 是冥炎表现：

- `typ = 0`, `effect = 1792795`。
- `layer_default = 1`, `layer_max = 1`。

`91000246` 清除冥炎表现：

- `typ = 10018`, `data = [91000244]`。

### 主流程四：在冥界中无冥炎的惩罚

`91000231` 是冥界检测循环：

- `time = [-1,-1,1000,0]`，每秒触发。
- `target = [3]`，作用于玩家。
- `trigger = [91000232]`。

`91000232` 判断玩家是否在冥界：

- `typ = 30000`, `data = [91000228]`。
- 如果存在 `91000228`，触发 `91000233` 和 `91000238`。

`91000233` 是冥界内的表现模块：

- `effect = 1792793`。
- `time = [1100,1,0,0]`，用于每秒循环中略长于 1 秒的表现覆盖。

`91000238` 判断是否有冥炎：

- `typ = 30000`, `data = [91000237]`。
- 如果没有 `91000237`，走 `not_pass_trigger = [91000239, 91000249]`。

`91000239` 是冥界无冥炎惩罚伤害：

- `typ = 97`, 即值类型伤害。
- `data = [0,1,0]`。
- 配有 `dataCondition = [[9,212,-92,0,0,999,91000249,-92,0]]`，其中 `-92` 是技能参数 2。最终伤害数值需要结合战斗伤害流水和技能参数解析，不能只靠 JSON 直接下定论。

`91000249` 是惩罚层数/图标：

- `buff_icon = 20002`。
- `layer_default = 1`, `layer_max = 99`。
- 作用上看，它是无冥炎惩罚的累计标记。

### 主流程五：在凡世中携带冥炎的小额伤害

`91000241` 是凡世检测循环：

- `time = [-1,0,1000,0]`，每秒检测。
- `trigger = [91000242]`。

`91000242` 判断是否处于冥界：

- `typ = 30000`, `data = [91000228]`。
- 如果不存在 `91000228`，走 `not_pass_trigger = [91000243]`，即只在凡世继续判断。

`91000243` 判断是否携带冥炎：

- `typ = 30000`, `data = [91000237]`。
- 如果存在冥炎，触发 `91000245`。

`91000245` 是凡世携带冥炎时的小额伤害：

- `typ = 97`, 即值类型伤害。
- `data = [0,1,0]`。
- `dataCondition = [[9,212,-93]]`，其中 `-93` 是技能参数 3。结合 `monster_skill.json`，910002 的 `value3 = 7`，与文案中凡世携带冥炎的小额扣血相吻合。

### 死亡重置

`91000252` 是角色死亡事件：

- `kind = 2`, `typ = 20020`，即 `entryTypeWhenRoleDie`。
- `trigger = [91000225]`。

死亡后会走：

- `91000225`: `typ = 1902`, `data = [2,2,910002]`，将副本技能 CD 表现置为 0。
- `91000226`: `typ = 1052`, `data = [91000221,1,2]`，将按钮状态直接设置为 `1`。

也就是死亡后把按钮恢复到凡世可点击态，避免玩家复活后卡在冷却或错误 UI 状态。

### 需要注意的点

- `91000236` 虽然在 `skill_entry_model_monster3.json` 里定义，但它的触发来自其他技能链路，例如其他 `91000xxx` 模块的 `next = [91000236]`。所以它是「被命中后尝试给冥炎」的公共入口，不是战斗开始自动发的模块。
- `not_pass_trigger` 在这里非常关键：`91000230` 用它表示“不在冥界则进入冥界”，`91000238` 用它表示“在冥界但没有冥炎则惩罚”，`91000242` 用它表示“不在冥界则检查凡世冥炎扣血”。
- `91000239` 和 `91000245` 的具体伤害最终值需要结合 `typ = 97` 的伤害处理、`dataCondition` 和技能参数 `-92/-93` 解析。仅从模块关系上可以确定它们分别对应“冥界无冥炎惩罚”和“凡世带冥炎惩罚”。
